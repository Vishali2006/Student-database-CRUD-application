# Student Database CRUD API

A small REST API for creating and managing student records. It is built with
FastAPI, Pydantic, and SQLite, and includes interactive API documentation and
automated tests.

## Features

- Create, list, retrieve, replace, and delete student records.
- Generate a unique numeric ID for each student.
- Filter the student list by course (case-insensitive exact match).
- Validate email addresses, phone number formatting, and dates.
- Require at least one contact method: email or phone.
- Return clear HTTP errors for missing records and duplicate email addresses.
- Store data in a local SQLite database that persists across restarts.
- Test the API against isolated temporary databases.

## Requirements

- Python 3.10 or newer
- `pip`

The dependencies are listed in [`requirements.txt`](requirements.txt).

## Install

Run these commands from the `student_crud_app` directory. On Windows, use
PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks virtual environment activation, use Command Prompt:

```bat
.venv\Scripts\activate.bat
```

On macOS or Linux, create and activate the environment with:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Run the API

Start the development server from the project directory:

```bash
python -m uvicorn main:app --reload
```

The service runs at <http://127.0.0.1:8000> by default.

- Interactive Swagger UI: <http://127.0.0.1:8000/docs>
- ReDoc: <http://127.0.0.1:8000/redoc>
- OpenAPI schema: <http://127.0.0.1:8000/openapi.json>

Stop the development server with `Ctrl+C`.

## API reference

All request and response bodies use JSON. Student IDs are generated by the
database and are included in responses.

| Method | Path | Description | Success response |
| --- | --- | --- | --- |
| `POST` | `/students` | Create a student | `201 Created` with the student |
| `GET` | `/students` | List all students | `200 OK` with an array |
| `GET` | `/students?course=Computer%20Science` | Filter by course | `200 OK` with an array |
| `GET` | `/students/{student_id}` | Get one student | `200 OK` with the student |
| `PUT` | `/students/{student_id}` | Replace a student's editable fields | `200 OK` with the updated student |
| `DELETE` | `/students/{student_id}` | Delete a student | `204 No Content` |

Course filtering uses a case-insensitive exact match. An empty list is returned
when no students match.

### Student fields

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `name` | string | Yes | 1–100 characters after trimming whitespace |
| `date_of_birth` | date | Yes | ISO format (`YYYY-MM-DD`); cannot be in the future |
| `email` | string or `null` | One contact method | Must be a valid email; must be unique |
| `phone` | string or `null` | One contact method | 7–30 characters; digits and `+().-` spaces only |
| `course` | string or `null` | No | Up to 100 characters |
| `address` | string or `null` | No | Up to 250 characters |
| `enrollment_date` | date or `null` | No | ISO format (`YYYY-MM-DD`) |

For both `POST` and `PUT`, provide the complete set of editable fields. At least
one of `email` or `phone` must be present. Optional fields may be omitted or set
to `null`. Blank optional text is treated as `null`.

### Create a student

`POST /students`

```json
{
  "name": "Alex Example",
  "date_of_birth": "2002-04-15",
  "email": "alex@example.com",
  "phone": "+1 (555) 010-1234",
  "course": "Computer Science",
  "address": "123 Example Street",
  "enrollment_date": "2024-09-01"
}
```

Example using `curl`:

```bash
curl -X POST http://127.0.0.1:8000/students \
  -H "Content-Type: application/json" \
  -d '{"name":"Alex Example","date_of_birth":"2002-04-15","email":"alex@example.com","course":"Computer Science"}'
```

Example using PowerShell's `curl.exe`:

```powershell
curl.exe -X POST http://127.0.0.1:8000/students `
  -H "Content-Type: application/json" `
  -d '{"name":"Alex Example","date_of_birth":"2002-04-15","email":"alex@example.com","course":"Computer Science"}'
```

### Error responses

| Status | Meaning |
| --- | --- |
| `404 Not Found` | The requested student ID does not exist |
| `409 Conflict` | The email address is already assigned to another student |
| `422 Unprocessable Entity` | Request body or query parameter failed validation |

FastAPI returns a JSON `detail` value with error information. The interactive
documentation at `/docs` also shows each operation's request and response
schemas.

## Run tests

With the virtual environment active and dependencies installed, run:

```bash
python -m pytest
```

Tests use temporary SQLite files and do not read or modify the development
database.

## Database

At startup, the application creates `students.db` beside `main.py` if it does
not already exist. The database file is ignored by Git, so local student data is
not committed. To reset local data, stop the server, delete `students.db`, and
start the server again. The database and table will be recreated automatically.

## Implementation notes

- `main.py` creates the FastAPI application and exposes `create_app()` so tests
  can supply an isolated database path.
- `schemas.py` validates input and formats response models.
- `database.py` uses parameterized SQL statements for database operations.
- SQLite creates the table during application startup; no separate migration
  command is required for a fresh database.
